# BPMN-модели бизнес-процессов

| Пара | «Как есть» | «Как должно быть» |
|---|---|---|
| Публикация и обновление игры | `as-is-publication` | `to-be-publication` |
| Управление игровыми серверами | `as-is-servers` | `to-be-servers` — подготовка в основном потоке, обслуживание серверов — развёрнутый подпроцесс (запуск по политике, подключение игрока, очередь); сбой, простой, команда разработчика и снятие игры с публикации — граничные события с обработчиками |

Исходники — `*.drawio` (draw.io), рядом экспорт в SVG и PNG. Схемы генерируются сценариями из `src/`
(`src/build.sh`); ручные правки в `.drawio` при пересборке перезаписываются.

## Сравнение процессов

Подсчёт по задачам на схемах (обе пары вместе).

| Показатель | Как есть | Как должно быть |
|---|---|---|
| Участников-людей | 4: разработчик, модератор, инженер, менеджер | 2: разработчик, модератор |
| Ручных задач инженера по эксплуатации | 5 | 0 |
| Ручных задач менеджера | 2 | 0 |
| Передач через мессенджер | 8 | 0 |
| Автоматических задач | 3 | 12 |
| Задач разработчика | 10, из них 5 — запросы другим участникам | 12, все выполняются самостоятельно; 3 — необязательные или альтернативные ветки |
| Задержка получения статистики | до 30 дней | не более суток |

Новые возможности, которых в «как есть» не было: командная работа над проектом, собственные
вычислительные узлы, очередь игроков, автоматический перезапуск при сбое и остановка при простое.
