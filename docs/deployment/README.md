# Диаграмма развёртывания

UML-диаграмма развёртывания системы: `deployment.drawio`, экспорт — `deployment.png` и `deployment.svg`.

Диаграмма собирается генератором `src/deployment.py` с явными координатами, поэтому правки вносятся в него, а не в `.drawio`:

```bash
python3 src/deployment.py deployment.drawio
drawio -x -f png -s 2 -o deployment.png deployment.drawio --no-sandbox
drawio -x -f svg -o deployment.svg deployment.drawio --no-sandbox
```

Состав сверен 11.11.2026 с продуктивным стеком `deployments/docker-compose.prod.yml`, шаблоном Nginx (`src/frontend/nginx.prod.conf.template`) и сервисами в `src/`:

- **Сервер платформы.**
  - Снаружи запросы принимает Nginx площадки (TLS) и передаёт их в Nginx стека. Тот отдаёт SPA, проксирует `/api` в API-шлюз, а `/game-proxy` во входной прокси; игры и медиа раздаёт из SeaweedFS.
  - Четыре gRPC-сервиса: модерация вызывает управление проектами и оркестрацию, управление проектами — модерацию, оркестрация — управление проектами (проверка прав на проект).
  - Опубликованные игры сервис управления проектами размещает прямо в объектном хранилище (режим `s3`). Агент развёртывания веб-игр (`src/game-deployment-agent`) в продуктивный стек не входит: это альтернативный режим публикации `agent` для отдельного сервера раздачи, поэтому на диаграмме его нет.
  - Хранилища: PostgreSQL, Valkey, SeaweedFS (S3).
- **Вычислительный узел.**
  - Агент узла один раз объявляет себя оркестратору на порт `:50052`. Дальше оркестратор сам опрашивает узел, управляет им и получает журналы через порт `:44044`.
  - Экземпляр игрового сервера сообщает агенту число игроков по HTTP на порт `:44045`.
  - На узле работают экземпляры игровых серверов и сервисы данных игры с резервными копиями.
- **Подключение игрока.** Через входной прокси платформы или напрямую по домену узла.
- **Смежные системы.** Почтовый сервер (SMTP) для сервиса учётных записей, сервисы аналитики и покупок площадки для сервиса управления проектами.
